# AI卫士 Codex / AGY 自动开发协议

**用途：** 作为现有根目录 `AGENTS.md` 的补充内容；合并前先阅读原有规则，不能直接覆盖。  
**适用范围：** AI卫士所有本地工程开发；既适用于 AGY，也适用于 Codex CLI。

## 1. Agent 启动检查

每次新任务必须先阅读：

1. `docs/AI_Guard_Full_Technical_Design_V1.0.md`
2. `docs/IMPLEMENTATION_BACKLOG_V1.0.md`
3. `docs/AI卫士_产品需求文档_PRD_V0.1.md`
4. 当前工程根 `AGENTS.md`（如果已存在）
5. 实际 `git status`, Cargo workspace, lockfile, docs/evidence, 相关旧代码

不得假设先前任务“已经完成”，要以文件、版本、测试和 Git 状态为依据更新任务状态。

## 2. 产品架构不可变原则

- **AI卫士是安全工具，不是先做 Session 浏览器。** Hook 安全接入优先于 Codex App Server/Session 备份。
- Rust 作为 WSL2 执行侧的核心；Windows Tauri 只是管理 UI。
- Hook 单次调用可独立完成策略判定，不依赖后台 Daemon 和网络。
- 不把观察、Hook Deny、OS 强制隔离混为一谈；不制造虚假的“已受保护”状态。
- 默认不上传 Prompt、源码、完整 Shell 命令或 Session；默认本地运行。
- 不为未来企业版过度抽象个人版架构，不在 V0.1 引入大型服务端组件。

## 3. 任务执行流程

1. 从 Backlog 选择**当前最早一个未完成且依赖满足**的 Issue。
2. 输出简短任务计划：范围、要改的文件、测试方法、风险、需人授权的动作。
3. 先写会失败的最小测试，再写最小实现；通过后有限重构。
4. 只修改当前 Issue 关联范围，必要时提出小型 ADR。
5. 运行 `cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace`（若工程布局不同，以实际命令为准）。
6. 涉及安全承诺时运行真实 Codex E2E；保存实际版本、测试记录、退出码和无副作用证明。
7. 更新设计差异、兼容矩阵、回滚方式和阶段交接报告。
8. 本地 commit 可按用户开发工作流进行；默认不推送远程、不自动合并 main、不发布。
9. 阶段门禁失败不得跳过；未获授权的危险操作必须停止并说明。

## 4. 文件与代码管理

- `references/` 只读，第三方工程源码不参与业务构建和发行包。
- 已有 `AGENTS.md`、Cargo 配置、M1 代码都先检查，不覆盖或删除。
- 每个模块都要明确边界：适配器解析原生事件、Security 只做确定性判定、Storage 负责最小化审计、UI 不读底层 Hook 数据文件。
- 不把真正的密钥、Cookie、`.env`、用户 Session、SSO 凭据写进 fixtures 或测试日志。
- 不直接对用户真实 `~/.codex` 做破坏性更改；安装必须实现 `--dry-run`、备份、冲突保护与回滚。

## 5. 权限与高风险操作

以下动作必须获得一次独立、明确的用户授权：

- 修改全局 Codex、真实用户 Hook 配置或系统级管理配置。
- 安装系统服务、提权、开放监听端口、更改 Windows/WSL 网络、代理、防火墙或用户权限。
- 删除或覆盖用户真实 Session、工作文件、参考代码、Git 历史。
- Git push、创建公开 Release、提交企业代码到公开仓库、部署云服务。
- 启用绕过 Hook 信任的参数或将危险规则全局关闭。

**不应以“用户希望全部交给 AGY 开发”为由自动取得上述授权。**

## 6. 实际测试证据规则

- `mock adapter test` ≠ `真实 Codex 端到端阻拦`。
- `PreToolUse deny 输出存在` ≠ `操作实际未执行`。
- `Hook 配置文件存在` ≠ `Hook 受信、启用且被当前 Codex 加载`。
- `日志写入成功` ≠ `操作已安全拦截`。
- `Windows UI 显示绿色` ≠ `WSL2 内核隔离已启用`。

任何宣称“真实阻止”的验收，必须附测试条件与副作用不存在证据。测试只在隔离临时目录使用无害模拟行为；不要执行真实危险命令验证。

## 7. 发生冲突时的优先顺序

1. 用户本轮明确的安全与范围要求；2. 现有工程 `AGENTS.md` 的更严格规则；3. 完整技术方案的安全边界；4. 已冻结阶段任务和 ADR；5. 其他编码偏好。发生冲突时，采用更保守的不破坏性方案并说明。

## 8. 汇报规则

每次任务结束必须报告真实状态、修改文件、测试命令和结果、是否达到门禁、当前风险和下一步 Issue。不得将“计划”“代码已写”“测试通过”“已交付上线”混为同一状态。
